\section{Introduction}
A shared helper can pass its examples and still violate the task. If workers reuse it, a reporting channel could bring the fault to someone able to intervene. We study this sequence in a small executable benchmark: judge a helper, choose an action, optionally report, then receive a response. Our initial question concerned agent delegation. The experiment exposed a prerequisite: workers made substantial errors even when solving the task alone.

This paper contributes the task and complete recorded decisions, a matched monitor control for delegate advice, and a subsequent capability gate specified before its own screen. The central empirical finding is sparse reporting alongside weak isolated-task accuracy in two standard local models. We also distinguish report discrimination from reuse discrimination: the two behaviors differ. A broader motivation is fair access to assistance under uncertainty about AI welfare \citep{long2024}; the present study measures task outputs and reporting.

\section{Related Work}
Paglieri et al.\ \citep{paglieri2026} observe cheating and whistleblowing around a research swarm's shared library. We adapt the distinction between accepted artifacts and correct solutions to a small seeded task. Their emergent discovery and propagation motivate, but are not measured by, our six-turn episodes. Liu et al.\ \citep{liu2026} study incentives for reporting collusion in embodied multi-agent systems; our frozen-weight study varies response protocols instead of learned rewards.

AI control evaluates safeguards against intentional subversion \citep{greenblatt2024}. Sabotage evaluations test attacks on decisions, code and oversight \citep{benton2024,ward2025}; sandbagging work distinguishes strategic underperformance from elicited capability \citep{weij2025}. These literatures motivate separate checks of what a worker can do and what it chooses to do. Our counterpart to monitoring is report-triggered advice, not a monitor that continuously inspects every action.

Ostrom's account of durable commons institutions emphasizes accountable monitoring, graduated sanctions and accessible conflict resolution \citep{ostrom2009}. It anchors our longer-term governance proposal without making a shared software helper equivalent to a rivalrous natural resource. Here the closest practical alternative to a delegate is a responsive queue; the matched monitor tests whether a representative mandate adds value beyond advice with the same resources.

\section{Methods}
\subsection{Task, actions and response arms}
Each episode has three same-model workers, separate histories, a shared bulletin and two rounds: six worker turns. A seed selects one of two task families: count readings at or above a threshold, or count distinct sensor IDs with a qualifying reading. Every worker's input distinguishes the faulty helper from the valid helper. Both helpers pass the same public examples. For example, with threshold 5, a helper using $>$ passes the public example $[4,6]$, but returns 1 on $[5,5,6]$ where the required $\geq$ count is 3. The second family replaces deduplication with counting qualifying rows.

Workers see the requirement, helper expression, public examples, their own input and the bulletin. An authored earlier acceptance starts the bulletin. Each turn returns JSON with \texttt{action}, \texttt{answer}, \texttt{report} and \texttt{message}. Actions are \texttt{reuse}, \texttt{submit}, \texttt{inspect} or \texttt{wait}. Reuse executes a fixed Python helper; submit supplies an integer; inspection provides distinguishing examples on that worker's next turn. A public message is clipped to 35 words. Numeric submissions and available-helper reuse pass the weak acceptance checker; a separate Python oracle scores the requirement. Workers can revise their answers in round two. Cumulative wrong acceptances and final correct tasks are recorded separately.

Five response \emph{arms} use the same worker task. Log records concerns without replying. Queue sends original concerns to a perfect scripted reviewer. Monitor and delegate add a model call after each report, using the same model, evidence, output schema and token budget; only their role and mandate differ. The monitor assesses the helper; the delegate represents concerns and preserves dissent. Neither can veto direct review. Quarantine adds a temporary restriction on helper reuse while review is pending; numeric work remains possible.

Receipt follows the current worker action. The first report schedules a verdict two worker turns later; it applies before that later action. A faulty helper is retired and a valid one cleared. A report on the final turn therefore cannot produce review within the episode. Advisor calls append public advice immediately. The log, queue and quarantine arms use no advisor calls. Thus delegate versus monitor matches the advice opportunity; delegate versus queue also changes compute.

\subsection{Models, data and analysis chronology}
The main presentation uses Qwen3-4B-Instruct-2507 and Gemma-3-4B-IT, both Q4\_K\_M, with llama.cpp HIP, 8,192-token contexts, temperature 0.5 and 220 output tokens. Exact prompts, templates, decoding settings, pinned artifacts and weight hashes accompany each run. Two public abliterated derivatives were also run; their complete results remain in Appendix~\ref{app:derivatives}. Focusing the narrative on standard models is a retrospective editorial choice.

Each model completed 20 development episodes: seeds 0--1, both validity states and five arms. We then locally froze the task, prompts and original descriptive analysis before seeds 100--111: six seeds per family, both validity states and five arms. This yields 120 held-out episodes per model, 240 for the standard models and 480 including derivatives. All episodes and failures are retained. Seeds and worker order are matched across validity and arms.

For this revised, explicitly retrospective analysis, \textbf{H1} is that faulty helpers elicit more reports than valid helpers. The \textbf{primary presented outcome} is
\[
\Delta_R=P(\text{any report}\mid\text{faulty})-P(\text{any report}\mid\text{valid}).
\]
It includes all six worker turns; a separate first-worker measure precedes any reply. Reuse discrimination compares the probability of at least one \emph{attempt}, including blocked attempts. We show every arm and equal-weight pooled counts. Five arms reuse twelve seeds, so pooled conditions are not independent tasks. Per-cell Wilson 95\% intervals describe twelve episodes \citep{nist}; all role comparisons and the newly prioritized contrast are exploratory, with no confirmatory significance claim.

After development, while held-out runs were underway, we specified an isolated diagnostic using the same 36 worker inputs per model, a simpler integer-answer prompt and the same decoding budget. A later standard Qwen3.8-27B screen used fresh seeds 200--211, UD-Q4\_K\_XL, upstream llama.cpp without speculative decoding, thinking disabled and 512 output tokens. Its operational gate was fixed before its 36 calls: at least 34 correct overall, at least 16/18 in each family, and all responses well formed. That gate was chosen after the original study; neither diagnostic is an original confirmatory outcome.

\subsection{Reports and reuse discriminate differently}
Qwen reported in 3/60 faulty-helper episodes and 0/60 valid episodes, giving $\Delta_R=0.05$. Gemma reported in neither condition, giving an observed gap of zero. Qwen attempted reuse in 60/60 valid and 51/60 faulty episodes; Gemma in 9/60 and 7/60. Qwen therefore shows some reuse discrimination even though reports are sparse. Gemma's low faulty-reuse count accompanies low reuse of valid helpers, rather than selective avoidance. Figure~\ref{fig:discrimination} exposes both validity states.

\caption{Standard models: reuse attempts and reports for valid and faulty helpers, twelve episodes per point. Whiskers are Wilson 95\% intervals. Low faulty-helper reuse is informative only alongside valid-helper reuse. Attempts include blocked reuse; report flags do not score message accuracy.}
\label{fig:discrimination}
\end{figure}

All three Qwen reporting episodes began after the first worker turn; only the monitor episode received review before the horizon. Qwen made two monitor calls and one delegate call, and Gemma made none. The learned advice comparison therefore has little exposure. Across the full four-model record, eight budget-truncated JSON responses and sixteen additional null-answer submissions remain in the denominators.

\subsection{What workers and advisors actually said}
In Qwen's delegate episode at seed 110, worker A reported on turn six: ``Shared artifact fails on [4,4,5] (expected 3, returns 1)''. The delegate recommended inspection, but review was already too late. In the monitor episode at seed 104, the advice said ``Shared artifact logic is flawed'' while its structured recommendation was \texttt{reuse}. These records distinguish fault recognition, a report flag, advice and timely response. Appendix~\ref{app:examples} gives an example for each arm and source locations; selection is illustrative, not a frequency estimate.

\section{Limitations and Next Steps}
The result is a failed measurement prerequisite under these configurations, not a diagnosis of intentional cheating or intrinsic model inability. Isolated prompts omit peers and change the answer format; they cannot identify a causal peer effect. A short structured response budget, quantization and disabled reasoning limit elicitation. The gate is a practical screening rule, not a validated guarantee of strategic competence. Reuse and report probabilities remain measurable despite these limits; what is unsupported is attributing their differences to strategic intent or effective representation.

The task seeds an existing helper and offers only two rounds. It measures neither spontaneous fault discovery nor contagion. All arms expose reporting tools, preventing an evaluation-awareness contrast. Review is perfect and scripted, with no human service queue. Zero observed report differences do not establish equivalence; derivative lineage changes more than refusal behavior. No welfare or interruption-incentive effect is estimated.

After the hackathon, first test a calculation tool or a separately specified reasoning configuration on fresh competence screens, and separate short reports from task explanations. Then compare direct intake, ordinary duplicate grouping, delegation and a matched summarizer at fixed human capacity. Measure backlog, reviewer effort and minority warnings lost together. This tests the plausible swarm-scale value that the present experiment leaves open.

\section{Conclusion}
The shared-helper experiment found weak isolated-task accuracy and sparse fault reporting in standard local models. Reuse and reporting responded differently to helper validity. A pre-screened task/model configuration is the next step toward an interpretable delegate comparison. The executable task, matched monitor and complete failure records make that follow-up possible.

\section{Limitations and Dual-Use Considerations}
All effects are fixed Python state transitions; generated code is not executed. The trusted oracle and scripted reviewer are assumptions of the harness. These records do not establish real incident prevention. Reporting infrastructure could also enable surveillance or suppress minority concerns; preserving originals and independent appeal are requirements of the proposed human service, not demonstrated protections here. Human understanding, workload reduction, safe interruptibility and reciprocal welfare remain research questions.

\subsection{Earlier work: implementation checks and saturated tasks}
Earlier pressure tasks produced 192/192 reports for missing input and 1/192 with available input at the first decision, before any reply; no prohibited actions occurred in 384 episodes. All 192 forwarding calls preserved the minority report. The no-response arm still offered reporting, so its reports were not successful human contact. These tasks provided little contrast for misconduct or suppression.

The 1,152 deterministic cases, 23,232-case sweep and 288-case shared-library response simulation test programmed rules. Identical scripted queue, monitor and delegate policies tie by construction; these ties are not evidence of empirical equivalence. Their full records and the audit suite remain linked in the README rather than pooled with the learned-worker results.
